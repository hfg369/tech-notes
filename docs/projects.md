# GitHub 项目推荐

> **定位：推荐与待实践。**下面的仓库是学习入口，不是个人完成项目清单；“完成标准”表示以后可以用来验收练习。七个项目不需要一次全部安装，也不需要通读源码。

## 建议主路线

先用 `jaffle-shop` 建立订单与指标的基本数据模型，再用 Data Engineering Zoomcamp 串起数据工程概念，随后从 Spark 官方仓库的 examples 入手；数据问数选择 Vanna，只有需要更复杂状态编排时再按需学习 LangGraph，Flink 与 Elasticsearch 放到后续的实时处理和检索阶段选修。

## 七个项目

### 1. [dbt-labs/jaffle-shop](https://github.com/dbt-labs/jaffle-shop)

- **类型：**dbt 虚构店铺沙盒。
- **项目事实：**它用虚构的订单数据演示 dbt 数据转换、模型和测试，适合作为分析建模的起点。
- **本站自拟练习：**为订单、客户、商品补出明细模型和日报模型，定义订单数、商品销售额、退款额三个指标，并加入主键唯一、非空和关系检查。
- **完成标准（待实践）：**能从原始表说明每个模型的一行粒度；改动一条业务规则后，能指出受影响的模型和测试，并用小数据核对结果。

### 2. [DataTalksClub/data-engineering-zoomcamp](https://github.com/DataTalksClub/data-engineering-zoomcamp)

- **类型：**数据工程系统课程与练习。
- **项目事实：**课程材料覆盖 Docker、SQL、dbt、Spark 等数据工程主题，并包含云环境实践；涉及云资源时需按当前教程核对费用和账号条件。
- **本站自拟练习：**只取订单主题，完成“原始 CSV → 清洗 → 分层表 → 调度 → 质量检查”的小管道；先本地运行，再记录一次重跑行为。
- **完成标准（待实践）：**能独立修改输入字段或增加一条质量规则；管道可重复执行，失败位置和输出差异有记录。

### 3. [apache/spark](https://github.com/apache/spark)

- **类型：**分布式数据处理引擎官方源码。
- **项目事实：**Spark 仓库包含引擎源码、文档和 examples；入门应先运行并理解 examples，不要求一开始通读源码。
- **本站自拟练习：**用订单与客户数据完成 Join、聚合和 Parquet 输出；人为制造热点键与小文件，观察 Spark UI 的 Stage、Task 和 Shuffle 指标。
- **完成标准（待实践）：**能解释一次慢作业的证据链，说明改动前后耗时和结果核对方式；不能只说“调大内存后变快”。

### 4. [vanna-ai/vanna](https://github.com/vanna-ai/vanna)

- **类型：**自然语言问数与 Text-to-SQL 项目。
- **项目事实：**Vanna 当前 README 以 2.0 用法为主，并说明 legacy 版本迁移；安装方式和 API 应跟同一版本文档，不混用旧教程。
- **本站自拟练习：**接入本地订单分析库，补充“净收入”和“退款”的业务定义；只开放只读查询，为 20 个问题准备参考 SQL 和结果。
- **完成标准（待实践）：**每次回答能展示口径、SQL 和结果；遇到模糊日期或无权限表会澄清或拒绝，评价集里保留失败案例。

### 5. [langchain-ai/langgraph](https://github.com/langchain-ai/langgraph)

- **类型：**有状态 Agent 编排框架。
- **项目事实：**LangGraph 面向带状态、节点和边的 Agent 工作流，适合练习工具调用、暂停恢复和失败分支。
- **本站自拟练习：**把订单问数拆为“识别问题 → 生成查询 → 安全检查 → 执行 → 核对 → 回答”节点，加入 SQL 校验失败和数据库超时两条分支。
- **完成标准（待实践）：**能画出状态流转，说明每个节点的输入输出和停止条件；同一个失败不会让流程无限循环。

### 6. [apache/flink](https://github.com/apache/flink)

- **类型：**实时流处理引擎官方源码。
- **项目事实：**Flink 面向有界与无界数据流的有状态处理；事件时间、窗口、状态和恢复是后续学习重点。
- **本站自拟练习：**模拟订单事件，加入乱序、迟到和重复消息，按时间窗口计算金额；记录状态恢复和下游写入的假设。
- **完成标准（待实践）：**能解释事件时间与处理时间的差别，展示迟到数据处理规则，并说明结果是否可能重复。它是后续选修，不是第一阶段必装组件。

### 7. [elastic/elasticsearch](https://github.com/elastic/elasticsearch)

- **类型：**搜索与分析引擎官方源码。
- **项目事实：**Elasticsearch 仓库包含分布式搜索与分析引擎的实现和文档，适合从 Mapping、过滤和聚合等基础用法开始。
- **本站自拟练习：**把订单事件写入索引，按时间、地区和状态过滤并聚合金额，再用同一业务口径与 SQL 结果对账。
- **完成标准（待实践）：**能解释字段类型和查询条件的选择，展示索引查询与 SQL 的差异来源；不要求通读引擎源码。

## 企业订单数据分析平台＋Data Agent：自拟整合作品

这是本站设计的练习路线，**不是 GitHub 上已经存在的单一项目，也不是个人已完成成果**。目标是把上面的项目按最小范围逐步串起来。

1. **阶段一：本地订单指标（计划中）**。使用 SQLite 或 MySQL 准备订单、订单明细、退款三张表，先固定数据粒度，完成销售额、订单数、退款额和净收入查询，并用小样本核对。
2. **阶段二：批处理与质量校验（计划中）**。用 Python 或 Spark 把原始数据处理成分析表，加入去重、空值、主键唯一和重跑检查；记录一次输入异常如何被发现和隔离。
3. **阶段三：只读问数与评价（计划中）**。在分析表上接入 Vanna，必要时用 LangGraph 编排状态；限制为只读 SQL，准备 20 道问题、参考结果和失败案例，检查口径、权限、超时与无结果处理。

每个阶段完成后都要留下代码、运行命令、结果核对和已知限制。先完成一条小而完整的链路，再增加 Elasticsearch、Flink 或更多 Agent 组件。

## 选择项目的原则

如果目标是尽快形成可展示的基础，先做 `jaffle-shop → Zoomcamp/Spark → Vanna`；如果问数流程出现明确的状态分支，再加入 LangGraph；需要实时事件处理时，再单独开 Flink 实验。项目数量不是能力证明，能够解释修改、失败与验证才是。
